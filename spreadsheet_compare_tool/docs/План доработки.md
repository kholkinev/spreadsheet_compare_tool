# Устранение замечаний EDT в обработке «Сравнение табличных документов»

## Цель

Привести внешнюю обработку `ВнешняяОбработка.СравнениеТабличныхДокументов` к стандартам разработки 1С: устранить **177 замечаний EDT** (в т.ч. 11 ошибок), а также исправить логические дефекты, выявленные при анализе кода.

Описание обработки находится в файле docs/Описание обработки.md

Текущее состояние замечаний (проверено `GetMarkers`):

| Файл | Всего | Ошибки |
|---|---|---|
| `ObjectModule.bsl` | 86 | 3 × SU57 |
| `Forms/ФормаУпраляемая/Module.bsl` | 84 | 1 × undefined-method, 4 × SU254, 1 × SU100-связка |
| `Forms/ФормаВыбораЛиста/Module.bsl` | 5 | — |
| `Forms/ФормаУпраляемая/Form.form` | 2 | 2 × SU100 |
| `СравнениеТабличныхДокументов.mdo` | 0 | — |

**Прогресс:** после выполнения п. 1 по `ObjectModule.bsl` осталось **56 замечаний** (было 86), из них 3 ошибки SU57 (п. 2). SU72/SU66 закрыты полностью.

## Решения пользователя

1. **Глубина:** устранить маркеры EDT **и** исправить найденные дефекты логики (разница числовых колонок, шапка при последовательном сравнении, дубли ключей, проброс исключений).
2. **Файловый API:** мигрировать `НачатьПомещениеФайла` → `НачатьПомещениеФайлаНаСервер`.
3. **Мёртвый код:** удалять.
4. **`ФормаВыбораЛиста`:** удалить форму из состава обработки.

## Способы проверки

1. `GetMarkers` по каждому изменённому файлу (`ObjectModule.bsl`, `Forms/ФормаУпраляемая/Module.bsl`, `Form.form`, `.mdo`) — целевое состояние: **0 замечаний** любого уровня. Проверять итеративно, после каждого файла.
2. `mcp__syntax-checker__validate` для новых/переписанных фрагментов (хелперы сравнения, обработчики оповещения, `ПередЗагрузкойДанныхИзНастроекНаСервере`).
3. Ручная проверка в 1С:Предприятие (толстый и тонкий клиент):
   - выбрать два `xlsx` с разными листами — лист подставляется автоматически, ошибок нет;
   - сравнить два `mxl` с заголовком и без — шапка, цвета, блок «Разница» на месте;
   - включить «последовательное сравнение» — шапка и раскраска присутствуют;
   - включить «выводить разницу числовых колонок» — разница ненулевая при отличающихся числах;
   - «не учитывать регистр» + «обрезать пробелы» — в обоих режимах сравнения результат одинаков;
   - кнопки фильтров «все / отличия / только в 1 / только во 2»;
   - сохранить настройки формы, переоткрыть обработку — табличные части восстанавливаются без ошибок;
   - выбрать несуществующий файл — понятное сообщение, временный файл не остаётся в `%TEMP%`.

## Риски и краевые случаи

- **Объединение логики сравнения (п. 4.1–4.2)** — самое рискованное место: меняется поведение последовательного сравнения (начнёт применяться `ОбрезатьПробелы`, появится шапка). Требует ручной проверки на реальных файлах.
- **Удаление `Экспорт` у переменных модуля** — если обработку используют внешним кодом через `ОбработкаОбъект.ПризнакРавно`, это сломает вызов. В проекте таких обращений нет.
- **Миграция файлового API** меняет сигнатуры двух обработчиков оповещения; при ошибке в них файл просто не прочитается — проверять сценарий выбора файла.
- **Удаление формы** из `.mdo` — необратимо в рамках этой задачи; файлы формы удаляются, история остаётся в Git.
- Порядок работ: сначала `.mdo`/форма (п. 9), затем модуль формы, затем модуль объекта — чтобы не гонять `GetMarkers` по ссылкам на удалённый объект.
