# Spec Delta

## Purpose

Сравнение двух табличных документов схожей структуры (MXL, XLS, XLSX): сопоставление строк по ключевым колонкам, выявление различий в колонках сравнения и формирование раскрашенного результата за время, приемлемое для больших таблиц.

## ADDED Requirements

### Requirement: Сопоставление строк в обычном режиме
В обычном режиме система SHALL для каждой строки первого файла искать во втором файле строку, у которой совпадают значения всех ключевых колонок, и сопоставлять её не более чем с одной строкой второго файла. Строка второго файла, однажды сопоставленная, MUST NOT участвовать в дальнейшем поиске.

#### Scenario: Найдено одно совпадение
- **WHEN** строка первого файла имеет ключ, который встречается во втором файле ровно один раз
- **THEN** в результат выводится одна строка с данными обоих файлов и признаком «равны» или «отличаются»

#### Scenario: Совпадение не найдено
- **WHEN** ключ строки первого файла не встречается среди ещё не сопоставленных строк второго файла
- **THEN** в результат выводится строка с признаком «только в первом файле» и пустой частью второго файла

#### Scenario: Несколько строк с одинаковым ключом
- **WHEN** во втором файле несколько ещё не сопоставленных строк с тем же ключом
- **THEN** строка первого файла сопоставляется с первой из них в порядке следования во втором файле, а остальные остаются доступными для следующих строк первого файла

#### Scenario: Несопоставленные строки второго файла
- **WHEN** обход первого файла завершён и во втором файле остались несопоставленные строки
- **THEN** они выводятся в конце результата с признаком «только во втором файле» в порядке следования во втором файле

### Requirement: Правила сравнения ключевых значений
Ключевые значения строк SHALL считаться равными, если равны их значения после приведения типов, заданных для выводимых колонок. При включённой настройке «Не учитывать регистр» строковые ключевые значения MUST сравниваться без учёта регистра; значения других типов сравниваются как есть.

#### Scenario: Ключ без учёта регистра
- **WHEN** включена настройка «Не учитывать регистр» и ключевые значения отличаются только регистром букв
- **THEN** строки считаются сопоставленными

#### Scenario: Ключ с учётом регистра
- **WHEN** настройка «Не учитывать регистр» выключена и ключевые значения отличаются только регистром букв
- **THEN** строки не сопоставляются

#### Scenario: Числовой ключ без учёта регистра
- **WHEN** включена настройка «Не учитывать регистр» и ключевая колонка второго файла имеет тип «Число»
- **THEN** сравнение выполняется без ошибки, числовые значения сравниваются как числа

### Requirement: Определение различий в сопоставленных строках
Для сопоставленной пары строк система SHALL сравнить значения каждой пары колонок сравнения и признать строки отличающимися, если различается хотя бы одна пара. При включённой настройке «Обрезать пробелы» строковые значения колонок сравнения MUST сравниваться без начальных и конечных пробелов; при включённой «Не учитывать регистр» — без учёта регистра.

#### Scenario: Отличие в одной колонке
- **WHEN** у сопоставленной пары различаются значения одной колонки сравнения
- **THEN** строка получает признак «отличаются», а в колонках имён различий перечисляются имена именно этой колонки для первого и второго файла

#### Scenario: Различие только в пробелах
- **WHEN** включена настройка «Обрезать пробелы» и значения колонки сравнения различаются только начальными или конечными пробелами
- **THEN** колонка не считается отличающейся

### Requirement: Неизменность результата при оптимизации
Для одинаковых исходных файлов, диапазонов и настроек результат сравнения SHALL совпадать с результатом предыдущей версии обработки по составу и порядку строк, признакам, значениям ячеек, именам отличающихся колонок, раскраске, шапке, легенде цветов и числу найденных различий.

#### Scenario: Сравнение эталонных файлов
- **WHEN** выполняется сравнение файлов из `docs/examples` с фиксированным набором настроек
- **THEN** сохранённый в MXL результат совпадает с результатом, полученным предыдущей версией обработки на тех же настройках

#### Scenario: Раскраска отличающейся строки
- **WHEN** строка получает признак «отличаются»
- **THEN** цветами «Отличаются» окрашиваются только ячейки отличающихся колонок, как и до изменения

#### Scenario: Раскраска строк одного файла
- **WHEN** строка получает признак «только в первом файле» или «только во втором файле»
- **THEN** вся строка в частях первого и второго файла окрашивается соответствующими цветами, как и до изменения

### Requirement: Линейная зависимость времени сравнения от объёма
Время выполнения сравнения в обычном режиме SHALL расти не быстрее чем пропорционально суммарному числу строк двух файлов при неизменном числе колонок и доле отличающихся строк.

#### Scenario: Удвоение объёма данных
- **WHEN** число строк в обоих файлах увеличивается вдвое при неизменных колонках, настройках и доле отличий
- **THEN** время выполнения сравнения увеличивается не более чем в 2,5 раза

#### Scenario: Большие файлы
- **WHEN** сравниваются два файла по 50 000 строк и 15 колонок с включённой настройкой «Не выводить одинаковые строки» и долей отличий не более 10%
- **THEN** сравнение завершается без ошибок, а время фазы сопоставления строк составляет не более трети общего времени выполнения кнопки «Сравнить»

### Requirement: Не выводить одинаковые строки по умолчанию
Настройка «Не выводить одинаковые строки» SHALL быть включена по умолчанию, если у пользователя нет сохранённых настроек формы обработки. Сохранённое ранее значение настройки MUST иметь приоритет над значением по умолчанию.

#### Scenario: Первый запуск без сохранённых настроек
- **WHEN** пользователь открывает обработку впервые или после очистки настроек
- **THEN** флажок «Не выводить одинаковые строки» установлен, и одинаковые строки в результат не попадают

#### Scenario: Есть сохранённые настройки
- **WHEN** у пользователя сохранено значение настройки «Не выводить одинаковые строки», равное «Ложь»
- **THEN** при открытии обработки флажок снят, и одинаковые строки выводятся в результат

### Requirement: Отображение времени выполнения по фазам
После сравнения система SHALL отображать в тексте состояния формы число найденных различий, общее время выполнения и время основных фаз: чтение данных, подготовка данных, сопоставление и вывод, оформление результата.

#### Scenario: Успешное сравнение
- **WHEN** сравнение завершилось
- **THEN** текст состояния содержит число различий, общее время и время каждой фазы

#### Scenario: Сравнение прервано проверкой заполнения
- **WHEN** проверка заполнения настроек обнаружила ошибки и сравнение не выполнялось
- **THEN** время фаз не выводится, пользователь видит сообщения об ошибках заполнения
