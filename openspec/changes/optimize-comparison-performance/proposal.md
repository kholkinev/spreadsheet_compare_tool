# Proposal

## Why

Кнопка «Сравнить» на больших табличных документах работает минуты и дольше. Причины лежат в одном серверном вызове: обычный режим сопоставляет строки за время порядка произведения числа строк двух файлов (поиск по таблице без индексов плюс удаление найденной строки сдвигом массива), а построение результата делает дорогие вызовы на каждую ячейку и несколько повторных проходов по уже готовому документу. Дополнительно по умолчанию в результат попадают одинаковые строки, что многократно увеличивает и время вывода, и объём документа.

## What Changes

- Сопоставление строк в обычном режиме переводится на однопроходную схему: ключ строки вычисляется один раз, поиск идёт по хеш-карте, найденная строка помечается использованной вместо удаления из таблицы. Итоговая сложность — пропорциональна суммарному числу строк двух файлов. Семантика сохраняется: прежний порядок вывода, выбор первого ещё не использованного совпадения при дублях ключей, те же правила сравнения значений при включённых флагах «Обрезать пробелы» и «Не учитывать регистр».
- Построение результата избавляется от повторяющейся работы: карта выводимых колонок строится один раз на файл, объекты областей макета кэшируются, раскраска строк выполняется по данным, накопленным при выводе, а не отдельным проходом с повторным разбором текста и расшифровки. Расчёт ширин колонок ограничен 200 строками и от объёма данных не зависит, поэтому затрагивается только при подтверждённой значимости по замеру.
- Подготовка данных сокращается до необходимого: числовое преобразование пропускает значения, уже являющиеся числом, и не использует обработку исключений там, где значение заведомо не число; регистронезависимые колонки создаются только для колонок, участвующих в сопоставлении и сравнении.
- Настройка «Не выводить одинаковые строки» получает значение по умолчанию «включено» в метаданных обработки. **BREAKING** для поведения по умолчанию: в новом сеансе без сохранённых настроек одинаковые строки в результат не попадают. У пользователей, у которых настройки уже сохранены, значение остаётся прежним — миграция настроек в этой работе не выполняется.
- Время выполнения по фазам выводится в текст состояния обработки, чтобы эффект изменений был измерим на реальных файлах.
- Документация обработки актуализируется: значение по умолчанию и состав результата, требования к производительности.

## Capabilities

### New Capabilities

- `spreadsheet-comparison`: сравнение двух табличных документов схожей структуры — сопоставление строк по ключевым колонкам, определение различий, состав и оформление результата, настройки сравнения и требования к времени выполнения.

### Modified Capabilities

Нет: спецификаций в проекте до этого изменения не было.

## Impact

- `spreadsheet_compare_tool/src/ExternalDataProcessors/СравнениеТабличныхДокументов/ObjectModule.bsl`: `СравнитьТаблицы`, `ПолучитьСтруктуруОтбора`, `ВывестиСтроку`, `ВывестиПризнак`, `ВывестиПробел`, `ВывестиРазныеКолонки`, `РаскраситьСтроки`, `РасчетШириныКолонок`, `ПреобразоватьЧисловыеСтроки`, `ДобавитьРегистронезависимыеКолонки`, `ОтображениеРезультатаУстановитьОтбор`.
- `spreadsheet_compare_tool/src/ExternalDataProcessors/СравнениеТабличныхДокументов/СравнениеТабличныхДокументов.mdo`: значение по умолчанию реквизита `НеВыводитьОдинаковыеСтроки`.
- `spreadsheet_compare_tool/src/ExternalDataProcessors/СравнениеТабличныхДокументов/Forms/ФормаУпраляемая/Module.bsl`: вывод времени выполнения по фазам в `ТекстСостояния`.
- `spreadsheet_compare_tool/docs/описание-обработки.md`: описание нового значения по умолчанию, состава результата и требований к производительности.
- `spreadsheet_compare_tool/src/ExternalDataProcessors/СравнениеТабличныхДокументов/Help/ru.html`: описание флажка «Не выводить одинаковые строки».

Вне scope этой работы: смена представления результата (таблица значений вместо табличного документа), изменение передачи данных формы на клиент, переписывание алгоритма последовательного сравнения (он получает только общие ускорения вывода), исправление вывода разницы числовых колонок (требует отдельного решения) и исправление отбора результата, если проверка подтвердит его дефект.
