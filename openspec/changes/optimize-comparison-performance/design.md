# Design

## Context

См. `proposal.md` — Why. Ниже только состояние кода, которое определяет решения.

Точка входа — `ВыполнитьСравнение` (`ObjectModule.bsl:53`), вызывается из `СравнитьНаСервере` (`Forms/ФормаУпраляемая/Module.bsl:62-92`). Платформа проекта — 8.5.1 (`DT-INF/PROJECT.PMF`), значит доступны `ТекущаяУниверсальнаяДатаВМиллисекундах`, `Соответствие`, `Массив`, `Структура`.

Обычный режим (`ObjectModule.bsl:1006-1263`) на каждую строку первого файла:

- `ПолучитьСтруктуруОтбора` (`:1626`) создаёт новую `Структуру` и при `НеУчитыватьРегистр` делает `ВРег` значений;
- `Таблица2.НайтиСтроки(Отбор)` (`:1053`) — поиск без индексов, `Индексы.Добавить` в коде отсутствует;
- `Таблица2.Удалить(Строка2)` (`:1170`) — сдвиг массива строк;
- финальный блок (`:1211-1248`) выводит оставшиеся строки второго файла.

Вывод (`:1397-1459`): `Макет.ПолучитьОбласть(...)` и `ТабДокумент.Присоединить(...)` на каждую ячейку; внутри `ВывестиСтроку` — двойной цикл `Таблица.Колонки` × `ВыводимыеКолонки` с `НРег` на каждой строке.

Пост-обработка (`:107-206`) — второй проход по документу: чтение `Область("R"+i+"C1..C3")`, разбор `Расшифровка` через `РазложитьСтрокуВМассивПодстрокЛокальная` (`:449`), `ПолучитьЧисло` (`:209`, внутри `Попытка`) на каждую строку.

Подготовка: `ПреобразоватьЧисловыеСтроки` (`:1680`) — N×K `ПолучитьЧисло` с `Попыткой`; `ДобавитьРегистронезависимыеКолонки` (`:1652`) — N×K `ВРег` по всем текстовым выводимым колонкам второго файла, хотя результат нужен только для ключевых колонок.

`РасчетШириныКолонок` (`:1499`) ограничен 200 строками документа — от числа строк не зависит. `ОтображениеРезультатаУстановитьОтбор` (`:399`) читает `Область("R"+i)` и прерывается на первой строке, где колонка 1 не число; поведение подозрительное, но структуру вывода менять не планируется.

Флаг `НеВыводитьОдинаковыеСтроки` входит в сохраняемые настройки формы (`Form.form:3329-3331`, `saveDataInSettings=UseList`); `defaultValue` в `.mdo` нет ни у одного реквизита.

Автотестов в проекте нет; проверка результата — сравнение MXL до и после на файлах `docs/examples` и на синтетических наборах.

## Goals / Non-Goals

**Goals:**

- Сопоставление строк в обычном режиме за время, пропорциональное суммарному числу строк.
- Снизить постоянные издержки вывода: убрать разбор имён областей и `НРег` из горячего цикла, убрать второй проход раскраски.
- Сократить подготовку данных до необходимого объёма.
- Сделать эффект измеримым на реальных файлах и проверяемым на эталонных результатах.

**Non-Goals:**

- Смена типа реквизита `Результат` (табличный документ остаётся), виртуализация отображения, изменение передачи данных формы на клиент.
- Алгоритм последовательного сравнения: он уже линейный, получает только общие ускорения вывода.
- Исправление вывода разницы числовых колонок (`:1462`) и отбора результата (`:399`): фиксируется текущее поведение, исправление — отдельное изменение.
- Оптимизация `РасчетШириныКолонок`: ограничен 200 строками, трогается только если замер покажет заметную долю.

## Decisions

### 1. Замер по фазам — до оптимизации

`ВыполнитьСравнение` накапливает длительности фаз в `Структуру` (чтение, подготовка, сопоставление, вывод, оформление) через `ТекущаяУниверсальнаяДатаВМиллисекундах` и записывает их вместе с `ВсегоРазличий` в реквизит `ТекстСостояния`; форма дописывает полное время вызова, включая `РеквизитФормыВЗначение` и `ЗначениеВРеквизитФормы`.

Альтернатива — профилировщик EDT: он не отражает работу собранного `.epf` в целевой среде, а оценка «на глаз» не проверяема. Замер остаётся в коде: он дешёвый и нужен пользователю при разборе больших файлов.

### 2. Ключ строки и хеш-карта вместо `НайтиСтроки` + `Удалить`

```
Для каждой строки файла 1 (в прежнем порядке):
    ключ = КлючСтроки(Строка1, СопоставлениеСтрок, "1")
    узел = Карта.Получить(ключ)                      // Соответствие: ключ -> Структура(Номера, Курсор)
    пока узел и Номера[Курсор] не пройден:
        если КлючиСовпадают(Строка1, Таблица2[Номера[Курсор]]):  // точная перепроверка
            взять строку, Курсор+1, пометить использованной, прервать
        иначе Курсор+1                               // коллизия строкового ключа
    если не взяли -> «только в файле 1»
Остаток: обход Таблица2 по порядку, некспользованные -> «только в файле 2»
```

- Ключ — строка: для каждой пары сопоставления префикс типа (`ТипЗнч`) и `Строка(значение)` после нормализации, разделитель `Символ(1)`. Нормализация (СокрЛП при `ОбрезатьПробелы`, `ВРег` при `НеУчитыватьРегистр` для строк) выполняется одной функцией для обоих файлов.
- Ключ — только ускоритель: кандидат всегда перепроверяется тем же сравнением, что применяется сейчас, поэтому коллизии `Строка()` (например, разное представление чисел) не меняют результат. Ложные несовпадения при одинаковой нормализации невозможны.
- Дубли ключей: массив номеров в порядке следования второго файла плюс курсор воспроизводят текущую FIFO-семантику «первая ещё не использованная строка». Помеченные использованными строки не удаляются, поэтому нет сдвига массива и пересборки индексов.
- Построение карты — один проход по второму файлу, ключи первого файла считаются по одному разу.

Альтернатива — `Таблица2.Индексы.Добавить(...)` + `НайтиСтроки`: платформа не гарантирует использование индекса для произвольного набора полей отбора, откат в линейный поиск произойдёт молча и обнулит выигрыш; кроме того, `НайтиСтроки` возвращает все совпадения, и для FIFO всё равно нужен курсор, а `Удалить` ломает индексы. Отклонено.

### 3. Отказ от регистронезависимых колонок

`ДобавитьРегистронезависимыеКолонки` (`:1652`) создаёт в таблице второго файла колонки `<Имя>Регистр` для всех текстовых выводимых колонок, но используются они только в `ПолучитьСтруктуруОтбора` и только для ключевых колонок. Вместо этого нормализация выполняется в `КлючСтроки` для обеих сторон одинаково.

Сохранение поведения: для нестроковых значений `ВРег` не применяется — как и в текущем `ПолучитьСтруктуруОтбора` (`:1639`). Краевой случай — колонка объявлена «Текст», а значение не строка: текущий код применил бы к нему `ВРег` без проверки типа; после изменения значение сравнивается как есть. Проверяется на эталонных файлах; при расхождении колонки сохраняются, но строятся только для ключевых колонок.

Побочный плюс: из таблиц уходят лишние колонки, меньше памяти и один проход `ВРег` на N×K исчезает.

### 4. Карта вывода и кэш областей

- Один раз на файл строится карта вывода — массив «имя колонки в таблице, имя для параметра» в том порядке, в котором колонки идут сейчас (внешний цикл — `Таблица.Колонки`, фильтр — вхождение в выводимые). Порядок вывода сохраняется, `НРег`-сравнения из цикла строк уходят.
- Объекты областей `Строка|Колонка`, `Строка|Признак`, `Строка|Пробел`, `Строка|РазныеКолонки1/2` кэшируются в `Соответствии` на время сравнения; параметры выставляются перед каждым `Присоединить`. Платформа копирует содержимое области в документ при `Присоединить`/`Вывести`, поэтому повторное использование объекта безопасно — это подтверждается микротестом до внедрения (см. Risks).

### 5. Раскраска без второго прохода

Признак и имена отличающихся колонок известны в момент вывода. Номера колонок в документе берутся из `СоответствиеИменКолонок1/2`, которые и так строятся в `ВывестиШапку`; границы частей — из `СтруктураДокумента`. Диапазон строк блока определяется по `ТабДокумент.ВысотаТаблицы` до и после вывода блока.

Цвета применяются сразу после присоединения областей блока, по тем же правилам, что в `РаскраситьСтроки` (`:140-200`): для «отличаются» — только отличающиеся колонки в обеих частях и колонки разницы; для «только в файле» — вся часть первого и второго файла и разница. Чтение `Область(...).Текст`, разбор `Расшифровка` и `ПолучитьЧисло`/`Попытка` из этого пути исчезают.

`РаскраситьСтроки` остаётся в модуле как экспортная процедура (внешняя совместимость), но сравнение её больше не вызывает; удаление — отдельным решением.

### 6. Подготовка данных

- `ПреобразоватьЧисловыеСтроки`: список колонок с типом «Число» собирается один раз (сейчас `ТипЗначения` проверяется N×K). Уже числовые значения и пустые строки не проходят через `Попытку`; `СтрЗаменить` применяется только при наличии соответствующих символов.
- `ДобавитьРегистронезависимыеКолонки` удаляется вместе с вызовом (`:91-93`), см. решение 3.

### 7. Значение по умолчанию для `НеВыводитьОдинаковыеСтроки`

В `.mdo` реквизита добавляется значение по умолчанию «Истина» (в EDT — через свойство реквизита; в XML это `defaultValue` у типа `Boolean`). Миграции сохранённых настроек нет: у пользователей с сохранённым значением остаётся их значение, как и согласовано.

Альтернатива — принудительно ставить `Истина` в `ПередЗагрузкойДанныхИзНастроекНаСервере`: не отличает «настроек ещё нет» от «есть сохранённое Ложь» без маркера версии, то есть требует машинерии миграции. Отклонено по решению пользователя.

### 8. Проверка эквивалентности и производительности

- Эталон: текущий `.epf` (`spreadsheet_compare_tool/bin/СравнениеТабличныхДокументов.epf`) прогоняется на `docs/examples/small_*.xlsx` и на синтетических наборах (дубли ключей, пустые ключи, числа/даты, отличия в одной и нескольких колонках, режимы с флагами и без), результаты сохраняются в MXL.
- После изменений те же прогоны сравниваются с эталоном по тексту ячеек, оформлению (цвет фона/текста), ширине колонок и числу различий — программным обходом двух MXL, а не побайтовым сравнением файлов.
- Производительность: наборы 5k/20k/50k строк × 15 колонок, доля отличий 1%/10%/100%, с включённым «Не выводить одинаковые строки»; фиксируются фазы из `ТекстСостояния`. Критерий спеки — удвоение объёма не более чем в 2,5 раза по времени сравнения.

## Risks / Trade-offs

- [Переиспользование объекта области не копирует значения при `Присоединить`] → микротест на двух присоединениях с разными параметрами до внедрения; при отрицательном результате кэш областей отменяется, остаются решения 1-3 и 5.
- [Строковый ключ даёт ложные совпадения на числах/датах] → обязательная точная перепроверка кандидата; тесты на 1 vs 1.0, даты с временем, пустые и `Неопределено`.
- [Изменение семантики дублей ключей] → тест FIFO: три строки второго файла с одним ключом, две строки первого; проверяется, какие пары сопоставлены.
- [Удаление `Регистр`-колонок меняет поведение на «текстовой» колонке с нестроковыми значениями] → прогон на эталонах; при расхождении — компромисс: колонки остаются, но только для ключевых полей.
- [Значение по умолчанию перекрыто сохранёнными настройками] → ожидаемое поведение по решению; в документации и в тексте задачи для замеров указывается, что флаг нужно включить вручную.
- [`defaultValue` в `.mdo` записан некорректно] → реквизит меняется средствами EDT, проверяется сборкой `.epf` и открытием формы без сохранённых настроек.
- [Память на очень больших файлах] → карта хранит по массиву номеров на ключ; на 50k строк это единицы мегабайт. При 500k+ строк потребуется отдельное решение, в этой работе не проверяется.
- [Эквивалентность результата при переписанной раскраске] → сравнение оформления с эталоном на всех сценариях, включая режим «выводить разницу» (даже если разница фактически пустая).

## Migration Plan

Обработка внешняя, данные не мигрируются. Выкладка — замена `.epf` в месте подключения дополнительных обработок. Откат — предыдущий `.epf` из `bin` (сохраняется в репозитории до выкладки). Сохранённые настройки пользователей не затрагиваются; меняется только значение по умолчанию для тех, у кого настроек нет.

## Open Questions

- Нужно ли исправлять вывод разницы числовых колонок и отбор результата — решается отдельным изменением; здесь фиксируется текущее поведение.
- Нужен ли индикатор прогресса (`мИндикатор` объявлен, но не присваивается): подключение меняет поведение формы и в эту работу не входит.
